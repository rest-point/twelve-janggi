# League-Trained Packed MLP + PUCT + DFPN

최신 터널 대전 결과는 [모델 보고서](../docs/models_report.md)의 M07을 참고한다. 아래 학습과 선별 수치는 배포 가중치를 고른 당시의 실험이다.

`packed-gemm-puct-v2`는 별도 정책·가치 MLP를 Packed GEMM으로 배치 평가한다. PUCT는 가상 방문 수로 여러 리프를 묶어 탐색하며, DFPN은 강제승을 증명한다. 루트에서 상대의 즉시 승리와 증명된 강제승을 검사하고, 검사를 통과한 대안이 있으면 증명된 패배 수를 제외한다. 탐색을 충분히 마친 루트에서는 방문이 충분한 후보의 평균 가치에 소표본 감점을 적용한다.

가중치는 `azero-v2`에서 초기화한 뒤 네 차례 리그 학습으로 갱신했다. 배포 모델은 자체 `packed-gemm-puct-v2.bin`을 읽는다. 이 체크포인트의 SHA-256은 `0c197430606fd1b118e103cbe4fbdc0a188eac51aeca4d02de10dd1a57a17d30`이다.

총 2,880국, 신규 표본 33,488개를 생성했다. 리그에는 자기 대국과 고정 `azero-v2`(800회 PUCT), PVS, 단일 PUCT, 배치 PUCT, 기존 Packed PUCT를 사용했다. R4에서는 챔피언 상대 대국 비중을 50%로 높였다. 정책에는 방문 분포와 탐색 가치를 사용하고, 가치에는 공식 대국 결과와 증명된 종국을 사용했다. R4는 R2와 R3 표본을 재사용했다. 각 라운드 설정, 시드, 가중치 해시와 표본은 `artifacts/packed-league-r*/`에 기록했다. 선별 실험은 공통 시드 271201을 사용했으며 R3부터 탐색 설정도 바뀌었다. 선별 점수 차이에는 가중치와 탐색 설정의 효과가 모두 포함될 수 있다.

배포 후보는 가장 높은 선별 득점률을 기록한 R4 체크포인트와 최대 3,200회 시뮬레이션, 수당 자체 상한 360ms를 사용한다. 배치 크기는 8이며 기존 `js-v1`에서 실행된다.

탐색 설정과 선별 국면 50개를 고정하고 가중치만 바꿔 100국씩 비교했다. 초기 가중치는 37승 27무 36패(50.5%), R4 가중치는 42승 27무 31패(55.5%)였다. 두 실행의 수 선택 시간 중앙값은 모두 약 360ms였다. 이 비교는 모델 선별에 사용한 국면에서 수행했다. 초기 가중치 대조 기록은 `artifacts/packed-league-initial-control/`에 있다.

```powershell
node scripts/evaluate.mjs --a packed-gemm-puct-v2 --b azero-v2 --games 480 --concurrency 4 --opening-plies 10 --move-ms 1000 --max-plies 240 --seed 271301
```

최종 판정에는 학습이나 선별의 시작 국면과 일치하는 대국을 제외한다. `train/paired-score.mjs`는 동일 시작 국면을 묶어 95% 구간을 추정한다. 승격 기준은 최소 400국, 득점률 55% 이상, 95% 구간 하한 50% 초과, 모델 실행 오류 0건이다.

공식 대전 480국의 기보를 모두 검증했다. 전체 결과는 221승 70무 189패로 득점률 53.33%였다. 기존 실험과 시작 국면이 겹친 16국을 제외하면 231개 시작 국면에서 215승 66무 183패를 기록했다. 득점률은 53.45%, 시작 국면을 묶어 계산한 95% 구간은 52.04~54.98%였다. 모델 실행 오류는 0건이었다. 득점률 55% 기준에 미달해 승격 판정은 보류한다.

같은 수당 1,000ms 제한에서 수 선택 시간 중앙값은 신규 모델 360.7ms, `azero-v2` 81.5ms였다. 이 결과는 각 모델의 배포 설정에서 측정했으며, 같은 탐색 시간으로 맞춘 비교는 수행하지 않았다. 공식 대전 기록은 `artifacts/2026-11-07T08-31-54-895Z-4994b2bc/`에 있다.

기본 시작판에서 선후공과 진영을 교대한 4국은 모두 반복 무승부였다. 네 기보를 모두 검증했으며 실행 오류는 0건이었다. 이 대전 기록은 `artifacts/2026-11-07T08-41-48-546Z-7bb2e929/`에 있다.

## 테이블베이스를 적용한 가중치 탐색

아래 명령을 직접 실행하면 `strict-v2` 초기 국면과 시드로 만든 시작 국면에서 부분 테이블베이스를 먼저 생성한다. 후퇴 분석으로 확인한 승패만 저장한다. 미해결 국면과 계산 범위 밖은 미확정으로 남긴다. 저장된 증명의 수순은 매 단계 종국까지의 상한이 감소한다. 이미 두 번 나타난 국면이 그 수순에 포함될 가능성이 있으면 해당 조회 결과를 건너뛴다.

```powershell
& "$env:LOCALAPPDATA\Programs\Python\Python311\python.exe" `
  train/packed-weight-sweep.py --out artifacts/packed-tb-sweep-01 --build-tablebase --rounds 3
```

라운드마다 동일한 테이블에서 기존 가중치와 정책·가치 출력층을 바꾼 후보 6개를 평가한다. 승수가 가장 많은 후보를 다음 라운드의 시작점으로 삼으며, 동률이면 득점률로 결정한다. 변경 폭은 라운드마다 절반으로 줄인다. 기본 설정은 후보별 48국, 검증 대상별 192국이고 테이블베이스를 쓰는 선별·검증 모두 모델 설정의 3,200회/360ms 제한을 적용한다. 다시 만들 필요가 없다면 `--build-tablebase` 대신 `--tablebase artifacts/packed-tb-sweep-01/tablebase.bin`을 사용한다.

`sweep.json`은 새 시작 국면에서 같은 가중치의 테이블베이스 적용 전후와 같은 테이블베이스의 가중치 변경 전후를 별도로 비교한다. 승률·득점률 차이와 시작 국면별 95% 구간을 기록한다. `best-screen.bin`은 선별 결과이며, 실전 적용 여부는 독립 검증을 기준으로 판단한다. 부분 테이블에는 50수 이상 증명이나 특정 시작판의 해가 없을 수 있다. 생성 시 증명 길이와 대전 중 적용 횟수를 기록한다.
