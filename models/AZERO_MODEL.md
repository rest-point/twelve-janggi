# AlphaZero MLP + MCTS (`azero-v1`)

원격 `azero-v1` 브랜치의 커밋 `f408e44af67bf0843e68ebe3ab86a201afc73a6e`를 기존 팀 모델·StockJang이 있는 로컬 `temp`에 병합했다. 등록 ID는 `azero-v1`, 화면 이름은 **AlphaZero MLP + MCTS**다. 기존 7개 모델을 포함해 총 8개 모델을 선택할 수 있다.

## 구성과 실행

- `azero-v1.mjs`: `js-v1` 모델 진입점. 가중치를 한 번 로드하고 요청마다 탐색 트리를 만든다.
- `azero-core.mjs`: 내부 규칙 구현, 기물·포로·반복 상태 인코딩, MLP 추론, PUCT MCTS.
- `azero-v1.bin`: 915,668바이트의 Float32 학습 가중치. manifest `files`에 core와 함께 선언되어 웹 Worker의 읽기 권한에 포함된다.
- 모델은 요청한 진영을 기준으로 좌표를 정규화하고 정책·가치 출력을 사용한다. 기본 `config`는 `{ "sims": 800 }`이며 루트의 방문 수가 가장 많은 수를 반환한다.
- `train/`에는 자기 대국 생성, 역전파, 학습, 별도 arena 스크립트가 있다. 로컬 모델 적용 과정에서는 학습을 실행하지 않는다. 학습하려면 별도의 출력 경로를 사용하고, 배포 가중치·코드·config 변경은 [model.md](../model.md)에 따라 새 ID/version으로 등록한다.

새 의존성이나 DB 마이그레이션은 없다. Node.js 24.7 이상에서 기존 앱과 같은 방식으로 실행한다. `npm start` 후 플레이어 vs AI 또는 모델 대전에서 **AlphaZero MLP + MCTS**를 선택한다.

```powershell
npm run setup
npm test
npm run build
node scripts/evaluate.mjs --a azero-v1 --b minimax-v1 --games 4 --concurrency 2 --opening-plies 0 --move-ms 60000 --max-plies 256 --seed 20261104
```

`tests/azero.test.js`는 무작위 400대국에서 자체 규칙·반복·종국을 기존 엔진과 비교하고, 수치 미분으로 역전파를 확인하며, 탐색의 반복 횟수 복구와 왕 진입을 검사한다. 추가 통합 테스트는 8개 모델 보존, 가중치 크기·유한성, 실제 웹 permission supervisor/128MiB Worker에서 양쪽 초기 차례의 응답과 재사용을 확인한다.

## 확인한 원본 모델의 한계

`azero-v1.mjs`는 요청의 `budgetMs`를 사용하지 않고 설정된 시뮬레이션 횟수를 모두 실행한다. 원본 설정은 800회다. 짧은 CLI 예산에서는 기존 실행기가 시간 초과로 종료할 수 있으므로 실제 예산으로 검증한다.

탐색 코어의 기본 `maxPly`가 절대 착수 수 256이며, 진입점에서 이 값을 조정하지 않는다. **엔진상 진행 중인 `state.ply >= 256` 국면을 웹 Worker에 요청하면 `model-error`가 발생하는 것을 확인했다.** 첫 수부터 진행하는 웹 모델 배치는 기존 심판이 256수에 무승부로 종료하므로 이 국면을 호출하지 않는다. 사람 대국에는 256수 제한이 없으므로 이 모델을 사용하는 장기 사람 대국에서는 문제가 될 수 있다. 임의 오프닝을 포함해 절대 착수 수가 256 이상이 되는 CLI 대국에도 주의가 필요하다.

이 문서의 통합은 원격에 게시된 `azero-v1`의 코드·가중치·설정을 그대로 사용한다. 시간 관리나 사람 대국의 전체 수 제한을 수정한 배포는 별도의 새 모델 버전으로 처리해야 한다. 자체 규칙의 무작위 일치 검증과 소수 연결 대국은 전체 기력이나 최적 플레이의 증명이 아니다.
