# `strict-v2` 전체 국면 테이블베이스

`FullTablebase.cs`는 기본판에서 합법 수를 따라 도달 가능한 고유 국면을 전부 방문한다. 차례인 쪽을 항상 0번으로 정규화한다. 차례가 바뀔 때 판을 180도 돌리고 진영과 손패를 교환하므로 양쪽 선공 기본판은 동일한 키를 갖는다. 별도의 좌우 대칭 축약은 적용하지 않는다. 왕 둘과 장·상·자 계열 각각 두 기물로 이루어진 기본판의 기물 구성이 대상이다.

정규화한 판과 손패를 64비트 키에 담고, 왕 위치와 기물 배치로 배열 인덱스를 계산한다. 역방향 간선은 저장하지 않는다. 후퇴 분석 중 이동·포획·포로 투입·승급을 역으로 적용하고, 순방향에서 확인된 국면만 이전 국면으로 인정한다. 승자가 최단 승리, 패자가 최장 방어를 택할 때 종국까지 걸리는 수를 기록한다. 닫힌 그래프에서 양측 모두 승리를 강제할 수 없는 국면은 무승부다.

```powershell
$dir = New-Item -ItemType Directory -Force artifacts/full-tablebase
$source = (Resolve-Path train/FullTablebase.cs).Path
$exe = Join-Path $dir.FullName 'FullTablebase.exe'
$table = Join-Path $dir.FullName 'strict-v2-full.bin'
& "$env:WINDIR\Microsoft.NET\Framework64\v4.0.30319\csc.exe" /nologo /optimize+ /platform:x64 "/out:$exe" $source
if ($LASTEXITCODE -eq 0) { & $exe solve $table }
node train/verify-full-tablebase.mjs $exe $table
node train/audit-full-tablebase.mjs $exe $table data/laptop-dev.sqlite
```

출력 파일의 첫 8바이트는 `TJFULL01`이다. 뒤에는 왕 위치 쌍 74개당 `11,878,227`개의 16비트 리틀 엔디언 값이 이어진다. `0`은 기본판에서 도달하지 못한 슬롯, `1`~`180`은 무승부, `±(256 + 남은 수)`는 착수자 기준 승패다. `probe` 명령은 표준 입력에서 16진수 국면 키를 받아 해당 위치만 읽는다.

테이블의 승패는 정규화한 국면 그래프에서 계산한다. 실전 기보를 판정할 때는 공식 심판의 종국과 반복 판정을 먼저 적용한다. 저장된 승패 증명은 매 수 남은 수가 감소하므로, 이미 두 번 등장한 실제 국면 가운데 증명에 다시 나타날 가능성이 있는 국면이 있으면 해당 조회를 미확정으로 남긴다. 기보 감사 도구는 이 검사를 거친 결과에서만 피할 수 있었던 패배나 놓친 강제승을 집계한다.

| 항목 | 결과 |
| --- | ---: |
| 정규화한 도달 국면 | 153,012,948 |
| 합법 전이 | 700,951,053 |
| 착수자 승리 | 80,188,235 |
| 무승부 | 4,854,498 |
| 착수자 패배 | 67,970,215 |
| 최장 확정 수순 | 178수 |

기본판은 양쪽 선공 모두 이론상 무승부다. 0번 진영 선공의 첫 수 네 개(왕 4→1, 왕 4→9, 자 5→6, 장 8→9)는 모두 무승부를 유지한다. 1번 진영 선공은 180도 회전한 수가 대응한다. 좌표는 0부터 시작하는 내부 칸 인덱스다.

표본 국면 4,000개에서 공식 심판의 합법 전이 25,474개를 대조하고, 역전이와 테이블의 승패 및 종국 거리 관계를 검증했다. 기본판에서는 양쪽 선공의 무승부 수순을 공식 심판으로 재생했다. 현재 모델이 실제 대전에서 고른 무패 수순과 검증 범위는 [모델 보고서](../docs/models_report.md)에서 확인할 수 있다.

로컬 출력 파일은 `artifacts/full-tablebase/strict-v2-full.bin`이며 크기는 1,757,977,604바이트다. SHA-256은 `0962d8dfefcc5da3ffa50778dc15ddd59914faf7076b9d8345fecd01c224f042`이다. 파일은 오프라인 조회와 기보 감사에 사용한다.

## 홍 후공의 무패 증명

`prove-red`는 청 선공 기본판에서 순방향으로만 검사한다. 청의 차례에는 모든 합법 수를 허용한다. 홍의 차례에는 테이블에서 청 승리로 표시되는 수를 제외하고 나머지를 모두 허용한다. 홍에게 남는 수가 없는 국면이나 청이 이기는 종국을 발견하면 실패한다. 차례를 기준으로 정규화한 국면에 홍의 실제 차례 여부를 함께 저장한다.

```powershell
& $exe prove-red $table
node train/verify-full-tablebase.mjs --packed $table models/full-tablebase
```

검사는 국면 128,601,960개, 청의 합법 전이 191,750,648개, 홍의 무패 전이 312,801,374개를 확인했다. 홍이 둘 수 있는 무패 수가 없는 국면과 청의 승리 종국은 발견되지 않았다. 3회 반복은 경로를 더 일찍 무승부로 끝낼 수 있다. 앱 압축 테이블도 53,650페이지 전체의 승·무·패 및 종국 거리가 원본과 일치했다.

기존 모델은 테이블 조회 경로에서 무승부 이상인 후보를 먼저 남기고, 실제 반복 무승부는 테이블보다 먼저 판정한다. 따라서 표준 시작판에서 정상적으로 착수하는 동안 모델은 위 검사가 허용한 경로를 벗어나지 않는다. 시계나 실행 오류로 인한 패배는 이 증명의 범위 밖이다.
